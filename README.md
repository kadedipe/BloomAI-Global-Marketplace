# BloomAI Global Marketplace

BloomAI is a production-oriented botanical marketplace monorepo. The customer web application, transactional API, and ML inference API deploy and scale independently while sharing one repository and CI pipeline.

## Architecture

| Deployable | Path | Runtime | Responsibility |
|---|---|---|---|
| Web | `apps/web` | React/Vite static site | Customer marketplace UI |
| Marketplace API | `services/marketplace-api` | FastAPI/Python | Authentication, vendors and products |
| AI API | `services/ai-api` | FastAPI/Python | Image validation and isolated model inference |
| PostgreSQL | Render managed database | PostgreSQL 16 | Durable transactional data |
| Redis | Render managed Redis | Redis 7 | Cache/queue foundation |

Legacy training and capstone materials remain under `ai-services`, `backend`, `frontend`, and `docs`; they are excluded from production images.

## Run locally

```bash
cp .env.example .env
docker compose up --build
```

Open the web app at `http://localhost:5173`, marketplace API docs at `http://localhost:8000/docs`, and AI API docs at `http://localhost:8001/docs`.

## Deploy to Render

1. In Render choose **New > Blueprint** and select this repository.
2. Render detects `render.yaml` and proposes three services, PostgreSQL, and Redis.
3. Set `CORS_ORIGINS` on both APIs to the final web URL (for example `https://bloomai-web.onrender.com`). Set the web service's `VITE_API_URL` and `VITE_AI_API_URL` to the full HTTPS URLs of their respective services.
4. Apply the Blueprint. These Vite values are compiled into the static build, so trigger a new web build if you change them.
5. Verify `/health/ready` on the marketplace API and `/health/live` on the AI API.

`JWT_SECRET` is generated by Render. Never commit production secrets. The AI service intentionally does not download or execute an unverified checkpoint at startup. Provision a compatible model artifact and its adapter before enabling predictions; until then classification returns `503` instead of fabricated output.

## API quick start

```bash
curl -X POST "$API/api/v1/auth/register" -H 'content-type: application/json' \
  -d '{"email":"vendor@example.com","password":"strong-password","name":"Bloom Vendor","role":"vendor"}'
curl -X POST "$API/api/v1/auth/login" -H 'content-type: application/json' \
  -d '{"email":"vendor@example.com","password":"strong-password"}'
```

## Production controls

- Non-root, slim service containers
- Liveness and database readiness probes
- Environment-specific CORS
- Argon2 password hashing and expiring JWTs
- Validated requests and bounded image uploads
- CI tests, linting, frontend builds, and Docker builds
- Pull-request previews for the web service

## Development

```bash
make test
make lint
```

See `.env.example` for local configuration. Add Alembic migrations before the first backward-incompatible database schema change.
